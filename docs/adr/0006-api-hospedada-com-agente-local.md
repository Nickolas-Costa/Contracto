# ADR 0006 — API hospedada com agente local para integração empresarial

- **Estado:** futura
- **Data:** 2026-09-12
- **Contexto:** uma empresa pode querer integrar seu CRM ou ERP ao Contracto. A geração depende de arquivos, modelos, diretórios Windows, Ghostscript e, para RTF, Microsoft Word via COM. Mover tudo diretamente para uma API pública transformaria o produto local em serviço de processamento de dados pessoais.
- **Decisão:** se houver produto de integração empresarial, priorizar um agente Contracto instalado no ambiente Windows da empresa. A plataforma remota, se necessária, autentica clientes, envia somente comandos e recebe estado e referências de resultado; o agente local acessa os arquivos, executa Word/Ghostscript e grava o dossiê. Uma API hospedada que receba documentos e execute a conversão será considerada apenas após requisitos formais de produto, segurança, LGPD, operação e licenciamento.
- **Alternativas consideradas:** hospedar imediatamente a API de geração e conversão (exige infraestrutura e tratamento de dados antes da validação comercial); manter somente uma API loopback (não integra sistemas corporativos externos); trocar Word por conversor não equivalente sem validar modelos (risco de documentos divergentes).
- **Consequências:** a integração comercial inicial continua Windows-first e preserva a propriedade local dos documentos. A API hospedada futura exigirá autenticação de organização e usuário, autorização por escopo, auditoria sem PII, retenção e exclusão de arquivos, criptografia, fila persistente, isolamento por empresa, limites de uso, observabilidade, suporte, termos de tratamento de dados e verificação de licença do Word e dos componentes distribuídos. O formato de transporte deve usar identificadores de trabalho e URLs temporárias autenticadas, nunca caminhos locais do cliente.
- **Arquivos:** futuro agente local, contrato de integração, `docs/SPEC_PRE_WEBVIEW.md` e documentação comercial/privacidade a definir.
